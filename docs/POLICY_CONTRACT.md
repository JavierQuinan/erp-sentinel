# Policy and evidence contract v0.1 (proposed)
Use strict JSON as canonical MVP interchange; YAML optional only via hardened parser later. Policy contains schema_version, platform/version and cases. Case has unique id, principal fixture alias, active_company alias, allowed_companies list, model, operation (read/write/create/unlink), record fixture alias (except create), optional fields/payload fixture alias, expected (allow/deny). All aliases resolve via trusted manifest; no arbitrary method or arbitrary user ID. Validate active company membership, operation-specific fields and unique IDs. JSON Schema plus semantic validation.
Observation: case_id, observed (allow/deny/error/unsupported), reason_code, adapter_version, target_revision, fixture_digest, policy_digest. Comparison requires matching case, policy and fixture hashes, schema and platform versions. Baseline/candidate revisions are distinct. Evidence envelope records pinned Odoo and database versions, tool version, case results, artifact hashes; canonical ordering, no timestamps inside deterministic result digest.
A case passes only when observed equals expected. Regression: baseline pass and candidate mismatch; existing violation: both mismatch; improvement: baseline mismatch and candidate pass; unchanged pass; inconclusive: error/unsupported/missing/incomparable in either side. Never classify errors as denial. Gate: 0 all required cases pass, 1 policy violation, 2 invalid config/execution/inconclusive (takes precedence). Version changes require explicit compatibility review.
Example:
```json
{"schema_version":"0.1","platform":{"name":"odoo","version":"18.0"},"cases":[{"id":"B06","principal":"sales_a","active_company":"a","allowed_companies":["a"],"model":"sentinel.document","operation":"read","record":"doc_b","expected":"deny"}]}
```
